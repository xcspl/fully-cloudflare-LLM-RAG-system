**Date**: 2026-05-19 18:18 GMT  
**Chapter**: gAIa chatbot framework — design, build, deploy, test

## What We Built

A production AI chatbot with tool-based RAG (retrieval-augmented generation) running entirely on Cloudflare's edge infrastructure.

### Three Components

| Component | URL | Purpose |
|-----------|-----|---------|
| Chat Worker (`gaia`) | `gaia-api.earth-team.org` | Public API + chat orchestration |
| Data Worker (`gaia-data`) | `gaia-data.sumanta-7a8.workers.dev` | Ingestion pipeline + vector search |
| Chat UI (Pages) | `gaia-chat.pages.dev` | Static HTML, SSE streaming, collapsible think |

### Flow

```
User → Chat UI → Chat Worker (/chat)
                   ├── D1 (sessions, system messages)
                   ├── Data Worker → Vectorize + D1
                   └── AI Gateway → LLM → stream back
```

### Key Features

- **Tool-based RAG**: LLM decides when and how to search the knowledge base via `search_knowledge_base` function
- **Two-step ingestion**: Raw JSON → canonicalize (DeepSeek V4 Flash) → embed (bge-m3) → Vectorize + D1
- **Idempotent ingestion**: MD5(source + full data JSON) as deterministic slug — safe to re-run
- **SSE streaming**: Word-by-word response for simple queries; JSON for tool-based
- **Session persistence**: Full conversation (user + assistant + tool calls + results) saved to D1
- **Collapsible think blocks**: CoT reasoning preserved, hidden behind toggle
- **Two LLM providers**: Minimax M2.7 (chat) + DeepSeek V4 Flash (canonicalization) — independently configurable

## Infrastructure Decisions

### Why Cloudflare Everything

- Workers: global edge, zero cold start, $0 at dev scale
- D1: SQLite at edge, JSON support via json1 extension
- Vectorize: managed vector index, 10 KiB metadata per vector
- AI Gateway: caching, rate limiting, provider abstraction
- Workers AI (bge-m3): cheap embedding ($0.012/M tokens), 60k context
- Pages: free static hosting, automatic SSL

### Two Workers, Not One

Chat and Data are separate Workers connected via Service Binding. Why:
- Data Worker handles heavy ops (embedding, canonicalization, D1 bulk writes)
- Chat Worker handles real-time orchestration (streaming, tool loop, session mgmt)
- Independent scaling, independent deploy, independent failure domains
- Service Binding for internal calls (zero egress, zero latency)

### Why bge-m3

- 1024 dimensions, 60,000 token context window
- Multi-lingual (100+ languages)
- $0.012 per million tokens — embedding 1M tokens costs ~1 cent
- Available via Workers AI binding with zero latency

### Why Canonicalize Before Embedding

Raw text has noise, varied styles, filler words. An LLM distills each chunk to its factual essence. The embedding model works with clean, consistent text — much better retrieval accuracy than embedding raw content directly.

## Pitfalls & Solutions

### Pitfall 1: `VECTORIZE.query()` returns `matches`, not `data`

The CF API response is `{ matches: [...], count: N }`, but we assumed `{ data: [...] }`. Spent hours debugging zero search results.

**Fix**: Destructure `matches`, not `data`.

### Pitfall 2: `env.AI.run()` returns nested arrays

bge-m3 returns `{ data: [[n1, n2, ...]] }` — always a 2D array, even for single text input. The inner array may be a TypedArray.

**Fix**: Always use `Array.from(data[0])` to get a plain `number[]`.

### Pitfall 3: Vectorize metadata must be strings

`null` values in metadata cause silent failures. The vector appears inserted but is unqueryable.

**Fix**: Filter out null values with `Object.entries().filter(([,v]) => v != null)`.

### Pitfall 4: Worker-to-Worker HTTP calls fail

Fetching `workers.dev` URLs from within a Worker returns 404. Direct HTTP calls between Workers don't work reliably on the CF edge.

**Fix**: Use Service Bindings (`env.DATA_SERVICE.fetch()`).

### Pitfall 5: Minimax doesn't support `role: "tool"`

Minimax M2.7 returns `choices: null` when messages contain `role: "tool"`. It also 520s on `stream: true` combined with tool messages.

**Fix**: Convert tool results to `role: "user"` messages. Disable streaming when tool messages are present; use JSON for tool-based responses.

### Pitfall 6: Minimax always thinks (CoT)

M2.7 always generates `<think>` blocks. No toggle, no parameter to disable it. The thinking adds ~4s latency per call.

**Fix**: Accept the latency for now. Strip think blocks at the text level (before DOM). Offer collapsed "Show reasoning" toggle for transparency.

### Pitfall 7: `ExecutionContext` is not constructable

`new ExecutionContext()` throws because it's runtime-injected by the CF Workers environment.

**Fix**: Accept `ctx` in the fetch handler signature: `fetch(request, env, ctx)` and pass it through.

### Pitfall 8: Wrangler auto-generates configs

Putting a `static/` directory in the project causes wrangler to auto-generate `wrangler.jsonc` with `assets.directory`, swallowing the Worker's fetch handler.

**Fix**: Delete auto-generated `wrangler.jsonc`. Deploy static files separately via `wrangler pages deploy`.

### Pitfall 9: Multiple CF accounts with OAuth

Wrangler can't pick the right account when multiple are available.

**Fix**: Set `account_id` in `wrangler.toml`. Use `CLOUDFLARE_ACCOUNT_ID` env var. Or unset `CF_ACCOUNT_ID` and `CF_API_TOKEN` to use OAuth.

### Pitfall 10: Service Binding needs explicit `--name`

Without `--name gaia`, wrangler may deploy to a different Worker (e.g., `t--pp` from auto-generated config).

**Fix**: Always deploy with `--name gaia`.

## Architecture Rules We Followed

- **No brand names in code**: `callLlm`, `LlmConfig`, `LLM_API_KEY` — never Minimax/OpenAI/etc.
- **Embedding model in column names**: `embeddings-bge-m3` for the vector column
- **Vectorize index suffixed with model**: `gaia-docs-bge-m3`
- **Metadata keys standardized**: `canonical_text`, `d1_db_id`, `d1_row_id`, `external_url`, `user_id`, `embedding_model`
- **Dedup via content hash**: `MD5(source + JSON.stringify(data))` for idempotent re-ingestion
- **D1 JSON columns for extensibility**: 5-column tables with `data` JSON absorbing domain fields
- **CORS on API**: `Access-Control-Allow-Origin: *` for Pages frontend
