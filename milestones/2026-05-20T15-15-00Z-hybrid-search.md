# Milestone: Hybrid Search — FTS5 + Vectorize via RRF

**Date**: 2026-05-20 15:15 GMT  
**Chapter**: Hybrid search ends the "Steve problem" — short terms now instant

---

## The Problem

Pure vector search fails on short, common terms. "Steve" in 1024-dimensional space is close to everything and nothing. A user searching for "Steve" expecting Steve Galster gets weak, scattered results or misses entirely.

## The Solution

**Hybrid search**: FTS5 keyword search (BM25) + Vectorize semantic search (cosine) → merged via Reciprocal Rank Fusion (k=60).

```
query "steve"
  ├── Arm 1: FTS5 MATCH → Steve Galster (rank 1), Michael Mitchell...
  └── Arm 2: bge-m3 embed → semantic neighbors
       │
       ▼ RRF merge
  Top-K ranked results
```

## What Changed

- **D1**: `documents_fts` virtual table with FTS5 on title, content, canonical
- **Data Worker `/search`**: runs both arms in parallel, merges via RRF, returns one ranked list
- **Zero changes** to Chat Worker, LLM tools, or frontend — the search engine got smarter silently

## Why RRF

- Parameter-free (just `k = 60`)
- Handles incompatible score scales (BM25 has no upper bound, cosine is 0–1)
- Proven in research to consistently outperform single-arm retrieval
- Used by Vercel AI SDK, LangChain, LlamaIndex, and the cloudflare-rag reference

## Impact

- "steve" → Steve Galster found instantly (milliseconds via FTS5)
- "who runs freeland" → semantic match + keyword match
- "reforestation Kalimantan" → both arms contribute
- Search latency: max of the two arms, not sum (parallel execution)
