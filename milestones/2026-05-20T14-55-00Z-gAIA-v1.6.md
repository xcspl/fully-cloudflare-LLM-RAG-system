# Milestone: gAIa v1.6 — 502 Defeated, Tool Markers, Context Hygiene

**Date**: 2026-05-20 14:55 GMT  
**Chapter**: Three-day debugging campaign resolves persistent 502 errors

---

## The 502 Problem

After a "no results" search, every subsequent message in the same session returned 502. The Worker was alive (health check passed), but /chat returned `Empty LLM response`.

## Root Causes (Two Interacting Bugs)

### 1. Empty Tool Results

`searchViaDataWorker` returned `""` on errors or no results. This went directly into the tool result message as `content: ""`. Minimax M2.7 rejects empty tool content — returns `choices: null` → Worker returns 502.

**Fix**: Always return valid text from the search function. On error: `"[Search error: ...]"`. On no results: `"[Search returned no results. Answer from your own knowledge.]"`.

### 2. Protocol Messages in Context

Tool markers were saved to `chat_messages` as `role: "tool"`. When loaded as context on the next request, these became bare tool protocol messages without their paired `assistant(tool_calls)` message. Minimax expects tool messages to immediately follow assistant(tool_calls) — orphaned tool messages break the protocol → 502.

**Fix**: `loadChatHistory` converts `role: "tool"` → `role: "user"` when loading context. Tool markers become inline conversation notes, not protocol messages. The DB keeps them as `role: "tool"` for visibility.

## The Rule

> DB tracks everything. Context reads tool markers as user notes. Never smuggle protocol messages into history.

## Other Changes in This Milestone

- **Streaming tee**: `streamResp.body.tee()` captures assistant text for saving without blocking the client
- **Think blocks stripped at save**: Both streaming and non-streaming paths strip `<think>...</think>` before saving to `chat_messages`
- **Context only loads `user` + `assistant`**: Tool markers converted to `user`, tool results not saved
- **Compact tool markers**: `[Searched knowledge base: "query"]` — one-liner, no LLM call needed
- **Debug logging**: `console.error()` on all error paths, `_debug` field in response
- **UUIDv7**: Session IDs use RFC 9562 time-sortable UUIDs (from uuidjs/uuid, MIT licensed)
- **Streaming mandate**: Added to CLAUDE.md — fix streaming, don't retreat to non-streaming

## Key Decisions

- Tool markers use `role: "tool"` in DB, converted to `role: "user"` in context
- `saveMessage` uses `await` not `ctx.waitUntil` for critical saves (user, tool markers)
- Assistant responses use `ctx.waitUntil` (deferred, non-blocking)
- Streaming always tried first; non-streaming is the escape hatch, not the default

## What's Stable

- 3-turn conversations with tool calls: no 502s
- "No results" queries followed by follow-ups: no 502s
- Cross-session context: clean, no protocol pollution
- Streaming: saves assistant text via tee
- Tool markers: visible in DB, invisible to protocol
